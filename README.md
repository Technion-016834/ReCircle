# ReCircle ♻️

**פלטפורמה לגילוי צריכה מקיימת וכלכלה מעגלית בתל אביב-יפו**

פרויקט בקורס "הפיכת רעיון למוצר חי" · שימי פריש ואלון פרוינד

> **English summary:** ReCircle helps people in Tel Aviv-Yafo find second-hand shops, repair services, sharing points, food rescue, community gardens, eco-art and sustainable shopping near them. The repo holds a hand-labelled dataset of 303 real records (v0.2), a personal recommendation dashboard with offline map routing, and the spec for a 7-class text classifier (`Primary_Category`).

## מה זה ReCircle?

מידע על חנויות יד שנייה, בעלי מלאכה, מקררים קהילתיים, גינות קהילתיות ואירועי החלפות מפוזר בין אתרים, רשתות חברתיות ושכבות GIS של העירייה. ReCircle מרכזת אותו במקום אחד, מסווגת אותו ומציגה לכל משתמש את מה שמתאים לו ונמצא קרוב אליו.

קהלי היעד: צרכנים מודעי סביבה, משפחות, חובבי וינטג׳, סטודנטים וצעירים, וגם עסקים ויוזמות שרוצים להגיע לקהל הזה.

## מה יש כרגע

1. **מאגר נתונים v0.2:** 303 רשומות אמיתיות מתל אביב-יפו (147 עסקים, 103 יוזמות, 53 אירועים), 252 מהן עם מיקום. המקורות: שכבות ה-GIS של עיריית תל אביב, לוח האירועים העירוני ומקורות רשת נוספים. לכל רשומה יש קישור למקור וסטטוס אימות.
2. **דשבורד המלצות אישי:** שאלון קצר (שלב בחיים, גיל, תקציב, תחומי עניין, אזור), ציון התאמה 0 עד 100 עם הסבר, המלצות בקבוצות ומשוב "מתאים לי / פחות מתאים". במצב "חיפוש על המפה" נועצים סיכה ומקבלים זמני הגעה ומסלול ברחובות (הליכה, אופניים, תחבורה ציבורית, רכב), הכול בדפדפן בלי שירות חיצוני. הדירוג מבוסס כללים ואינו מודל ML.
3. **מפות וכרטיסי מידע (v0.1):** מפות עצמאיות עם רקע רחובות לא-מקוון מ-OpenStreetMap.
4. **אפיון משימת ML:** שני שלבים. קודם סינון בינארי מקיים / לא מקיים, ואחר כך סיווג לקטגוריה ראשית אחת מתוך 7.
5. **יומן סינון:** 2,128 אתרים שנבדקו, ולכל אחד החלטה והסבר מדוע אושר או נפסל (פירוט בהמשך).

## משימת למידת המכונה

| | |
| --- | --- |
| סוג המשימה | סיווג טקסט רב-מחלקתי |
| עמודת היעד | `Primary_Category` (תיוג ידני של רשומות אמיתיות, לא סימולציה) |
| קלט | `Name`, `Description_ML`, `Services` ותוכן פרסומי |
| פלט | `Predicted_Category` (הצעה בלבד, נבדקת לפני פרסום) |
| הערכה | Accuracy, Macro-F1, מטריצת בלבול, ביצועים לכל קטגוריה. חלוקה לפי `Entity_Group` כדי שאותו גוף לא יופיע גם באימון וגם בבדיקה |

## איך הוחלט אילו אתרים מקיימים (יומן הסינון)

**מה היה לפני כן:** ב-v0.1 וב-v0.2 הסינון נעשה רק בשלב בחירת המקורות. נאספו מקורות שעוסקים בקיימות מלכתחילה, ולא נרשם אף מועמד שנפסל. לכן לא שוחזרה רשימת פסולים בדיעבד. במקום זאת נעשתה ב-24.11.2026 סריקה חדשה ומתועדת.

**מה נבדק:** 303 הרשומות של v0.2 (שלב A), ועוד כל החנויות ובעלי המלאכה (`shop=*` / `craft=*`) שמופיעים ב-OpenStreetMap סביב תל אביב, 1,825 בסך הכול (שלב B). שלב B כולל עסקים רגילים, ולכן יש בו דוגמאות שליליות אמיתיות.

**הכללים** נבדקים לפי הסדר, והכלל הראשון שמתאים קובע:

| שלב | כלל | תוצאה |
| --- | --- | --- |
| 0 | המיקום מחוץ לגבול המוניציפלי של תל אביב-יפו (G1) | לא נבדק |
| 1 | ראיה מפורשת, מתגית OSM או ממקור נושאי, לאחד מקריטריוני הקיימות I1 עד I8 | מאושר |
| 2 | אין תגית מתאימה, אבל השם מעיד על הפעילות ("וינטג׳", "תיקונים", "refill") | מאושר, ומסומן לבדיקה ידנית |
| 3 | מקרה גבולי (R1): סופרמרקט אורגני, חנות חקלאית, עסק השכרה, או עסק שסוגו לא ידוע | ממתין להחלטת הצוות |
| 4 | אין ראיה לאף קריטריון. הסיבה נרשמת כאחד מהקודים X1 עד X6 | נפסל |
| עדיפות | אם התגית פוסלת אבל מקור נוסף מתעד פעילות מקיימת (למשל וינטג׳ שמסומן כחנות בגדים רגילה) | מאושר לפי המקור הנוסף |

קריטריוני ההכללה:
- I1 יד שנייה ושימוש חוזר
- I2 תיקון
- I3 מכירה ללא אריזה ומילוי חוזר
- I4 שיתוף והשאלה
- I5 הצלת מזון
- I6 אמנות מחומרים ממוחזרים
- I7 צרכנות מקיימת: מקומי, אתי, חקלאי
- I8 קהילה וטבע

סיבות הפסילה:
- X1 רק מוצרים חדשים
- X2 קמעונאות מזון רגילה
- X3 שירות שאינו מאריך את חיי המוצר
- X4 רכב ממונע
- X5 קניון, או עסק שאינו פעיל
- X6 אין מספיק מידע

**תוצאות:**

| אושרו | נפסלו | גבוליים | מחוץ לעיר | סה״כ |
| --- | --- | --- | --- | --- |
| 328 | 1,133 | 9 | 658 | 2,128 |

לכל שורה יש `Is_Sustainable` (עמודת היעד של מסווג הסינון), `Decision_Reason` (הסבר בעברית), `Evidence` וקישור למקור. בסיס האימון כולל 313 חיוביים ו-937 שליליים, ומספר השליליים מוגבל ל-1,000 לכל היותר.

**ממצא מרכזי:** תגית סוג העסק לבדה הייתה פוסלת 4 מתוך 10 עסקים מקיימים מוכרים. זו ההצדקה למודל שקורא טקסט.

**מגבלה:** לשליליים יש רק שם וסוג עסק, ולחיוביים יש תיאור מלא. לכן צריך לאזן את הקלט לפני האימון.

המתודולוגיה המלאה נמצאת ב-[`data/screening/METHODOLOGY_screening.md`](data/screening/METHODOLOGY_screening.md).

## הרצה מקומית

הדשבורד טוען קבצי JSON, ולכן צריך שרת סטטי:

```bash
python3 -m http.server 8000
# ואז לפתוח http://localhost:8000/
```

המפות והגלריה ב-`maps/` עצמאיות ונפתחות גם בלחיצה כפולה.

בנייה מחדש של הנתונים (Python 3, pandas, openpyxl):

```bash
python3 data/v0.2/build_v0.2.py                      # v0.1 + vintage + תוספות → v0.2
(cd data/screening && python3 -I build_screening.py) # יומן הסינון
cd data/recommender
python3 -I build_osm_bg.py ../osm_offline/tlv_streets_osm.json ../osm_offline/tlv_water_osm.json osm_bg.json
python3 -I build_routing.py ../osm_offline/tlv_streets_osm.json routing.json
```
